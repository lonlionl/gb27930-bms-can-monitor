# Doc/ui_preview/ —— 界面渲染效果图

这些 PNG 不是手绘的效果图，而是**程序真正渲染出来的帧**导出的，可以直接用来
核对界面长什么样，也可以作为项目报告/答辩的截图。

生成方式（在 Ubuntu 虚拟机上，不需要屏幕、不需要开发板）：

```bash
# ---- I.MX6ULL 端 ----------------------------------------------------------
cd ~/CAN
./run_gui_test.sh                       # 虚拟屏 + 脚本化触摸，跑完整链路
python3 tools/ppm2png.py /tmp/gui_frames --scale 1

# ---- STM32 端 -------------------------------------------------------------
cd <仓库根>
make -f tools/pc_ui/Makefile run        # 用 PC 编译 ui_app.c 并渲染
python3 tools/ppm2png.py /tmp/stm32_main.ppm
```

### 当前 I.MX 四页结构

| 页面 | 内容 |
|------|------|
| 主界面 | 三行读数 + 电池信息 + CAN/存储统计；右上角「数据曲线」「充电」两个按钮 |
| 数据曲线 | 标题栏「数据曲线」，右上角「历史」「返回」；顶部一排四个指标切换按钮，只换曲线不跳页；中间是本次充电的单条曲线；底部一行统计 |
| 历史九宫格 | 3×3 缩略图，最多 9 次充电记录，读 SQLite 的 `charge_session` 表 |
| 历史详情 | 某一次充电的完整曲线 + 参数 |

数据曲线页顶部那排指标按钮：`电压 V` / `电流 A` / `温度 C` / `电量 %`，各
110×18，x 起点分别是 8 / 123 / 238 / 353，y = 48，选中的那个蓝底高亮。

每条曲线有**固定的内部量程**，不随数据自适应：电压 400~600 V、电流 0~120 A、
温度 0~60 ℃、电量 0~100 %。固定量程之后，电压从 480 涨到 584 就只占它该占的
那一段高度；自适应的话一条斜线会拉满整个绘图区，看不出形状。

数据曲线页的横坐标是**电量增量**，不是时间轴：不管从 20% 还是 80% 开始充，
起点永远在绘图区最左边，0%→100% 正好铺满。底部只有一行
`HH:MM:SS->HH:MM:SS` 说明这次充电从几点几分到几点几分，没有时间刻度。

历史九宫格的缩略图按**电量的绝对位置**画（横轴 = 电量 0~100% 铺满格宽）：
50%→75% 就画在格子正中到四分之三处，0%→100% 正好铺满整格。每格还标了
`50%->75%` 和底部的时间段与电量。

## 帧序列能看出什么

I.MX 端在 `run_gui_test.sh` 里导出的是**一整套帧**，文件名是 `NN_main.ppm` /
`NN_curve.ppm` / `NN_grid.ppm` / `NN_detail.ppm`（`detail` 只在进了历史详情页
时才会有），序号就是重绘顺序：

```
  00_main .. 09_main                 主界面（前 2 秒，约 200 ms 一帧）
  10_curve 11_curve 12_curve         第 2 秒触摸「数据曲线」→ 切到数据曲线页
  13_grid .. 18_grid                 第 5 秒再触摸「历史」→ 切到历史九宫格
                                     第 8 秒点空白区域：帧序列没有变化 → 没有误触发
```

实测一次导出 19 帧：主界面 10 张、数据曲线 3 张、历史九宫格 6 张，共 19 张
（另外中间有一个序号是跳过的）。第 2 秒点的是「数据曲线」按钮，不是「历史曲线」。

所以这一串帧本身就是「界面随时间变化 + 触摸切页」的完整证据，而不只是一张
静态截图。

> **注意**：`--gui-rec` 是开发自检用的开关，正常运行时不要开。
> 它默认最多导 **24** 帧（`GUI_REC_DEFAULT_LIMIT`）；上面那次实测只导出 19 帧，
> 是因为界面总共只重绘了 19 次就退出，没够到上限 —— 24 是上限，不是实际帧数。
> 24 帧 × 480×272 × 3 字节 ≈ 9.4 MB，长时间开着会一直写磁盘。
